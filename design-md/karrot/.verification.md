## SEED BoxButton tokens — live re-verification (2026-09-17)

**Inspected:** 2026-09-17 · `https://v2.seed-design.io/component/box-button/usage/`
**Method:** headless Chrome. The usage page embeds its live preview in a Storybook
iframe; values were read from the **authored `--seed-box-button-*` custom properties**
resolved on the rendered button, not from the painted result.

Before this pass `box-button` carried only `type`, a prose `states` list and `use` — no
values at all. It now carries the declared primary colours.

| authored property | value |
|---|---|
| `--seed-box-button-primary-enabled-background` | `#ff6f0f` |
| `--seed-box-button-primary-enabled-color` | `#ffffff` |
| `--seed-box-button-primary-hovered-background` | `#ff9e66` |
| `--seed-box-button-primary-pressed-background` | `#ff9e66` |
| `--seed-box-button-primary-disabled-background` | `#dcdee3` |
| `--seed-box-button-primary-disabled-color` | `#adb1ba` |

**Pressed equals hover by declaration, not by measurement error.** Isolated runs confirm
the DOM states are distinct (`:hover` true / `:active` false, then both true) while the
background stays `#ff9e66`, and the authored property names it independently. Recorded
as a fact rather than collapsed.

**The product blue-orange is not the marketing orange.** SEED declares `#ff6f0f`; the
`marketing-primary` token in this reference is `#ff6600` from `karrotmarket.com`. Two
surfaces, two oranges — kept named apart, as with the TDS/marketing split in `toss`.

**A focus outline was observed and deliberately not recorded.** Keyboard focus paints
`rgb(0, 136, 204) solid 2px`. That blue belongs to no part of the Karrot palette and no
`--seed-box-button-*focus*` property exists, so it is Storybook's own preview chrome,
not a brand fact.

**Size and type scale were not promoted.** The preview renders a single 48px instance
while the reference documents five sizes; without knowing which size the preview shows,
no geometry claim was written.

### What was deliberately not declared

- `outline: #005fcc auto` on the listing card, footer link and category link is the browser default ring, not a brand value. Those components carry no `focus` key.
- `home::[data-omd-capture="7"]`, the search submit button, is `disabled: true` in the bundle (bg `#f7f8f9`, icon `#d1d3d8`). A disabled rest is not declared as a component.
- Sign In, the keyword links and the flag menu item have rest values only; no state was sampled, so none is written. The flag button was not re-probed on 2026-09-29, and its build class changed (`_2vdeyl0` → `u4us220`).

### Corrections

- `marketing-primary.states` said "hover not captured". That was literally true of the 2026-07-11 capture, which holds no state frame for this button. Hover and pressed do exist: a `::before` overlay paints them while the computed background stays `#ff6600`, and the capture's style dump records no pseudo-elements, so it could not have seen them either way.
- §6 said the public controls report `box-shadow: none`. That holds for the header pills at rest; the search wrapper and the flag menu carry shadows.
- The 2026-07-11 raw samples above cite `home::[data-omd-capture="0"]` for the `#ff6600` CTA and `"6"` for the disabled `#d1d3d8` control. In the bundle on disk those are captures `2` and `7` (capture 0 is an 80×30 link, capture 6 the search input). The values are right; the indices are not.
