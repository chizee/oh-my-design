## paging-button states — sought, and there are none (2026-09-17)

**Inspected:** 2026-09-17 · `https://search.naver.com/search.naver?query=디자인`
**Method:** `web/scripts/probe-component-states.mjs`, matched by the documented white
background at the documented 36px height.

The control was found and the DOM states registered correctly — `:hover` on the hover
pass, `:hover` and `:active` together on the press pass — so the states were genuinely
exercised, not missed. **Background and foreground are identical across all four
states** (`#ffffff` / `#1c1c1c`).

So this component's `hover` / `pressed` / `focus` stay absent because NAVER does not
change colour on them, not because they were not measured. Recorded so a later pass does
not re-spend a browser run on it.

Geometry: measured 36px tall with `border-radius: 50%`. The reference records `9999px`,
which renders identically on a square control; no geometry claim was changed.

### Corrections

- `paging-button.states` said hover and pressed were "not retained", and the 2026-09-17 section above concluded that NAVER does not change these controls. That check measured a search-results paging control (fg `#1c1c1c`), not the declared portal-home button (fg `#2e2e2e`). On the portal home, hover and pressed paint bg `rgba(0, 0, 0, 0.06)` and shadow `0 2px 4px rgba(0, 0, 0, 0.12)`.
- `search-input.states` said "focus ... observed". Keyboard focus changes nothing on the input; the green ring is a permanent `1px solid #03c75a` border on `div#search_area`.
- `search-submit.states` said "hover and pressed not retained"; both were exercised on 2026-09-29 and the control has no pointer response.
- The portal sign-in CTA fills `#03a94d`, not the brand `#03c75a`, which only tints its shadow. No existing claim said otherwise, but the reference had no component for it; it now has one, and `#03a94d` is in the palette as `login-fill`.
