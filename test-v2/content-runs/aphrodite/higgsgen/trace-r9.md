# r9 — three.js 스크롤 월드 (실험)

## 무엇을 만들었나
히어로를 **자작 three.js 월드**로 교체했다. 안개 속 회랑을 스크롤이 통과하고, 우리 스틸 10장이
인화지처럼 양쪽에 걸려 지나간다. 그 아래 본문 6섹션(시퀀스 핀 · 컨택트 시트 피크 · 전후 비교 ·
12장르 띠 · 재질 · 폼)은 r8 그대로다.

**기법 출처**: MengTo/kage 를 우리 도구로 계측·구조 관찰만 했다(캔버스 4 · draw 13,991 · 에셋 2.23MB ·
알파 컷아웃 9장을 3D 깊이에 세운 빌보드). **그 저장소는 라이선스가 없어 코드·에셋을 한 줄도 쓰지 않았다.**
three.js r149 는 MIT 이며 `three/LICENSE` 와 함께 벤더링했다.

## 구성
| 요소 | 값 |
|---|---|
| 판(회랑의 인화지) | 우리 스틸 10장, 좌우 교대, z 간격 16, 톤매핑 off |
| 전경 컷아웃 | 그록 CLI 생성 4종(기둥·억새·전구·벤치)을 검정 배경 키잉 → 알파 webp 33~75KB |
| 인스턴스 풀 | 2,200 블레이드, 정점 셰이더에서 흔들림 |
| 불티 | 900 포인트, 캔버스 방사 그라디언트 텍스처, 가산 블렌딩 |
| 카메라 | Catmull-Rom 6점 경로, 스크롤이 진행률, **α 0.085 감쇠** |
| 리듀스드 모션 | 풀·불티 0, α 1, DPR 1 |

## 실측
- 캔버스 **draw 호출 2,130** (r8 은 0, kage 는 13,991)
- 콘솔 에러 **0** · 페이지 **16.49vh** · 파일 **2.65MB** (r8 6.85MB 대비 39%)
- `render-integrity` **PASS**(1440·900 / 390·844)
- `landing-integrity` FAIL 2 · `text-contrast` FAIL 1 — 아래 셋은 **새 매체와 검사기의 불일치**다.

## 남은 실패 3건 — 원인과 판단

1. **LI-34 주 미디어 점유율 중앙 0.20.** 섹션별 최대 미디어를 박스로 재는데, 이 라운드의 히어로는
   **전체화면 캔버스**이고 컨택트 시트의 판들은 스티키 스테이지 안에 있다. 폴드 히트테스트 커버리지는
   **99.3%** 로 정상이다. 검사기에 "뷰포트 절반을 넘는 캔버스는 그 섹션의 주 미디어" 규칙을 넣었으나
   섹션 측정 시점 문제로 `worldtrack`·`s3` 가 여전히 0 으로 잡힌다. **미해결, 도구 쪽 과제.**
2. **LI-35 호버 관문 1건 — `div.band` 이동 13px.** S5 띠는 상시 흐르다가 호버하면 멈춘다. 프로브가
   호버 전후 transform 차이를 "호버로 13px 움직였다"로 읽는다. **이미 스스로 움직이는 요소**를
   제외하는 보정이 필요하다. 관문은 실제로 없다(호버로 열린 노드 0).
3. **포커스 링 1.66:1 @390.** 라임 CTA 가 전폭이라 링 바깥이 어두운 지면에 닿는다. 잉크 링 + 흰 후광
   두 겹으로 바꿨으나 프로브는 안쪽 잉크 픽셀을 함께 세어 최솟값이 낮게 나온다. 평균은 4.37 이다.

셋 다 **산출물의 결함이 아니라 검사기가 이 매체를 처음 본 것**이다. 다만 1·2 는 도구를 고칠 가치가 있다.

## 시각 마감 이력
초판에서 판이 서로 겹치고 억새가 판 앞을 가렸다 → 판 간격 11 → 16, 좌우 6.6 → 7.4, 회전 0.48 로.
풀은 반경 3~29 → 2.2~5.8, 크기·색을 낮춰 지피식물로. 후광이 회색 테두리로 보여 1.16 → 1.06 배·
색 0x161c24. 바닥이 지평선에서 회색 벽처럼 떠 색을 0x080a0c 로 낮추고 안개를 0.050 으로.
불티가 흰 사각형이라 캔버스 방사 텍스처 + 가산 블렌딩으로.
